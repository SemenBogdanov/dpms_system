# Настройки ширины разделов

Дата: 11.11.2026. Ветка: `feature/content-layout-preferences-20261111`.
Scope: frontend, без изменения backend-кода, миграций и пользовательских данных.
Пользователь отдельно согласовал production deploy после автоматических проверок,
без предварительной ручной приёмки в локальном Docker; 16.11 поручил продолжить.

## Контракт

В настройках добавлен раздел «Визуализация». Для каждого доступного пользователю
раздела можно выбрать «Во весь экран» либо симметричные боковые отступы.
Это ширина рабочей области рядом с меню, а не полноэкранный режим браузера.

- При снятии checkbox задаётся `10%` с каждой стороны.
- Допустимы `0–40%` с одним десятичным знаком. Сохранение числа по Enter/blur.
- Пустой или некорректный ввод не изменяет сохранённую настройку; ошибка находится
  рядом с полем. Конечные числа за пределами диапазона ограничиваются, дроби округляются.
- Изменение применяется сразу. Reset конкретной строки возвращает исходную вёрстку.
- До явного выбора исходная ширина страницы сохраняется. Checkbox имеет native
  `indeterminate`, а строка помечена «По умолчанию». Первый click включает полную ширину.
- «Во весь экран» снимает внешний `max-width`, сохраняя меню, внутренние отступы
  интерфейса, safe areas и собственную структуру раздела.
- Процент считается от доступной рабочей области после меню и штатного padding.
  Ниже `1024px` процентные отступы не применяются. На desktop они уменьшаются,
  если иначе ширина станет меньше минимума для соответствующего раздела.
  Минимум не может расширить область за доступные границы окна.
- Ограничения ширины: обычно `960px`; таблицы, проекты, аудит, календарь аудита
  и администрирование `1440px`; калькулятор `1120px`; знания и развитие `1100px`.
  Это ограничение вёрстки, а не ограничение доступа.
- Вложенные маршруты наследуют настройки своего раздела. Graphs сохраняет
  полный размер холста по высоте и существующие жесты.
- Список строится из существующего sidebar registry и access gates; дополнительно
  доступны профиль и два admin-раздела согласно их текущим правам.

## Хранение

Настройки персональные, только для текущего браузера. Они не загружаются на сервер
и не переносятся автоматически на другое устройство. Каждый раздел хранится
независимо под `dpms.contentLayout.v1:<userId>:<sectionId>`, чтобы одновременные
записи разных разделов из двух вкладок не перезаписывали друг друга. Для одного
и того же раздела действует последний записанный вариант.

Изменения видны сразу в текущей и других открытых вкладках этого пользователя.
Отсутствующий пользователь не инициирует чтение/запись. Повреждённые и неизвестные
записи игнорируются. При отказе localStorage настройка применяется в памяти;
строка явно сообщает «Применено только в этой вкладке».

## Проверка

```sh
cd frontend
npx --no-install tsc --noEmit
node --input-type=module -e 'import { build } from "vite"; await build({ envFile: false });'
node --test tests/content-layout-preferences.test.mjs
npx eslint src/components/Layout.tsx src/components/ContentLayoutSettingsPanel.tsx src/pages/SettingsPage.tsx src/lib/contentLayout.ts src/hooks/useContentLayoutPreferences.ts tests/content-layout.spec.ts playwright.content-layout.config.ts
npm run smoke:navigation
npx playwright test --config playwright.content-layout.config.ts
```

Browser suite использует изолированные синтетические API fixtures, Chromium,
desktop WebKit и iPhone WebKit. Проверяет переключение, reset, валидацию,
reload, несколько вкладок, недоступное хранилище, ограниченные права,
симметрию рамки и высоту iframe графов. Responsive matrix:
`320x700`, `390x844`, `1024x768`, `1440x900`, `1920x1080`;
темы light/dark/rose. Скриншоты находятся в `frontend/test-results/` и не публикуются в Git.

Проверка существующего пользовательского backend и production не подменяется
синтетическими browser fixtures. Результаты конкретного прогона и Git SHA
фиксируются в PersonalOS project log.

Локальная проверка 16.11: TypeScript, production build, scoped ESLint и shell syntax
PASS; 34 unit, 18 browser и 8 существующих graph/trackpad checks PASS. Navigation,
mobile readiness и 21 calendar access test также PASS. Независимый critic подтвердил
исправление межвкладочной гонки и корректное исходное состояние checkbox.

## Ручная приёмка

Использовать прежнюю точку входа `http://localhost:55177/graphs`, затем открыть
«Настройки» → «Визуализация». Проверить один узкий раздел и одну таблицу:
полная ширина, отключение с `10%`, собственное число, reload и reset.
На телефоне убедиться, что форма не требует горизонтальной прокрутки.
Production выпускается согласованным exact-SHA pipeline с preflight и postchecks.
