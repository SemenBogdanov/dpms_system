# Сценарий приемки календаря аудита

Сценарий подготовлен для локального кандидата. Сквозной допуск исправлен,
native browser runner прошел 40 проверок через обычный вход DPMS.
Это не production и не копия настоящего расписания.

Адрес: <http://localhost:5177/audit-calendar>.
Синтетические аккаунты: `calendar.helper@example.com` (помощник),
`calendar.employee@example.com` (сотрудник), `calendar.admin@example.com` (admin),
`calendar.outsider@example.com` (не включен в контур).
Публичный пароль только этого локального набора: `Calendar-local-2026!`.
Используйте разные профили браузера, чтобы не переключать учетную запись постоянно.

## Основной Путь

1. Войти помощником. После входа открываются «Сообщения». Перейти в «Календарь аудита».
   Должны быть четыре KPI, план и факт, группы G1/G2, два примера будущих встреч.
   Снятые встречи «Проверка сохранения chromium/webkit» оставлены как история автотеста
   и не увеличивают KPI плана.
2. Нажать пустое время завтра. Выбрать G1, активность, докладчика, 90 минут.
   При незаполненной доступности виден вопрос доступности, но назначение разрешено.
   Escape и случайный клик снаружи не должны стирать заполнение. После сохранения
   должна появиться одна встреча, а не три отдельных факта/плана.
3. Войти сотрудником в другом профиле. Он видит расписание, но не управляет нормами
   и чужими данными. В «Доступном времени» отметить себе полный день свободным,
   затем один интервал занятым. Помощник не может назначить встречу в этот интервал.
   У помощника нажать «Обновить календарь» для просмотра изменений коллеги.
4. Помощником добавить отсутствие сотрудника на несколько дат. Новое назначение
   с ним блокируется; прежний план не исчезает, а получает замечание.
5. В «Управлении» изменить общую норму 6 на 4 с сегодня, потом запланировать 0
   на будущую дату. Прошлая история сохраняется; отпуск не снижает целевые значения.
6. Для уже закончившейся встречи зафиксировать факт с основанием и подтверждением.
   После сохранения нельзя переписать факт/состав. Отмена не увеличивает выполнение.
   Для быстрого теста это действие можно проверить позже в тот же день; не подменяйте
   системные часы и не создавайте исторический факт без документа-основания.
7. Проверить период, фильтры, «Сегодня», 7/14 дней и журнал. Поиск/человек не должны
   уменьшать командную цель; выбор группы меняет расчет на группу.
8. На узком экране выбрать день: время, план и факт доступны без горизонтального
   скролла. Повторить в light/dark/rose, открыть и закрыть форму с черновиком.

## Права И История

Admin выдает допуск и отдельно включает пользователя в контур. Роль admin сама по
себе не дает права читать расписание или управлять им. Outsider с допуском, но без
участия, получает отказ. После отзыва допуска новая запись и повтор старой команды
должны быть запрещены.

В разделе «Импорт» JSON V5 проходит явное сопоставление и предварительный просмотр.
Подтверждение обязательно; повтор не создает дублей. Старый JSON без planning не
сбрасывает нормы. Первичный перенос норм возможен только в пустой контур с заранее
согласованным baseline и явными составами современных групп; G21 остается неизвестной.
Демонстрационный контур уже непустой: проверка полного bootstrap проводится отдельным
автоматизированным PostgreSQL-тестом. Реальные данные не загружать без согласования.

Справка доступна внутри календаря, а статья добавлена локальной миграцией в базу знаний.
