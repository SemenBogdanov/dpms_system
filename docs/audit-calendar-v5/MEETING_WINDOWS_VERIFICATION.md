# Доступные Окна: Локальный Кандидат

Дата: 14.09.2026. Worktree: `dpms-audit-calendar-v5`, ветка
`feature/calendar-availability-locks`. Новые изменения включены поверх ранее
подготовленного кандидата замков, отчетности и конкурентной доступности.
Production не изменялся. Commit/release не формировались.

## Поведение

- Отдельная строка окон рядом с планом/фактом; независимая группа не скрывается
  за уже занятой строкой плана. На телефоне отдельная колонка «Окна».
- Длительность 30 минут по умолчанию, докладчик и группа; параметры в URL.
  Быстрые последовательные изменения объединяются без потери предыдущего фильтра.
- Зеленый: есть подтвержденная тройка. Желтый: есть только допустимый вариант
  с неизвестной доступностью. Busy, отсутствие и недостаточный интервал блокируют.
- Счетчик — сочетания, не параллельная емкость. Открытие показывает точный состав,
  именные замечания и повторно проверяет сервер. Выбор открывает обычный защищенный
  черновик с CAS; автоматического создания встречи нет.
- Чужие по фильтру бронирования, действующие составы, отмены, факты и права
  проверяются общей доменной логикой. Архив и отсутствие полномочий не дают создавать.
- Ошибка, обновление, смена фильтров и отзыв допуска сбрасывают старые цвета/варианты.
  Возврат в видимую вкладку обновляет данные; новая частая polling-петля не добавлена.

## Review И Границы

Независимый read-only backend critic проверил соответствие diagnostics сохранения
и обнаружил два P2: чрезмерные вычисления и большой SQL IN. Оба исправлены;
повторный review без P1/P2. Независимый frontend worker выявил гонку URL, main
исправил ее и подтвердил browser regression. Также сохранена прежняя подпись
исторического докладчика, исключен повтор одинаковой ошибки периода.

Один batch на период/параметры, одинаковое число SQL-запросов для 1 и 31 дня.
Ограничения: 31 день, 2000 сочетаний, 50 000 проверок участник-интервал,
250 000 проверок сочетание-интервал, 20 000 строк на запрос контекста.
Превышение возвращает 422 с просьбой сузить подбор, не усеченный результат.
SQL-участники выбираются подзапросами; пустые кеши не разрастаются.
Вычисление отдает управление event loop каждые 8 стартовых интервалов.
Большой разрешенный запрос все еще может удерживать shared scope lock до окончания;
распределенный production load test не проводился.

Цвет — снимок на момент проверки, не бронь. Даже подтвержденный вариант может
измениться другим помощником; сохранение снова проверяет актуальные условия.
