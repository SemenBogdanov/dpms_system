# Доступное Время: Явное Сохранение

15.09.2026. Дополнение локального кандидата `feature/calendar-compact-layout`.
Production, backend, БД и соседние worktrees не менялись.

## Изменения

- Участник и «Отсутствие» перенесены в верхнюю полосу перед группой и KPI.
  Компонент доступности сохраняет владение черновиком; controls размещаются
  через стабильный React portal, без дублирования формы и обработчиков.
- Убраны повторяющиеся подписи `00:00–24:00` и «Закрыт» под кнопками дня.
  Полный день по-прежнему означает 00:00–24:00, это указано в title/aria-label.
  Замок остаётся четвёртой кнопкой; закрытый день имеет выделенный значок
  с временем фиксации в tooltip. Подача заявки и её статус сохранены.
- Период свёрнут по умолчанию во всех представлениях календаря. Размер окна
  не сбрасывает выбранное пользователем состояние раскрытия.
- Клики, выделение мышью и действия целого дня формируют общий черновик.
  «Сохранить» отправляет один пакет; отображается spinner, затем подтверждённое
  сервером «Изменения сохранены». Новая правка снова показывает кнопку.
- На телефоне можно переключать дни внутри черновика. Смена участника,
  отсутствие, фиксация дня, период и навигация защищены от потери ввода.
- Счётчик выделения расположен в существующей строке состояния и не сдвигает
  таблицу во время pointer-жеста.
- Clean Back/Forward переключает день по URL. После сохранения/отмены выбранный
  внутри черновика день остаётся на экране и синхронизируется с URL.
- При read-only просмотре закрытый день сохраняет пассивный Lock-индикатор,
  не предлагая недоступную операцию. Оба замечания независимого critic закрыты;
  повторный точечный review: GO.

## Сохранность

Первый ввод фиксирует исходный снимок доступности. Последующие изменения
нормализуются по получасовым ячейкам; возвраты к исходному значению исключаются,
соседние одинаковые ячейки объединяются. Даже полный период из 14 суток
укладывается в серверный лимит 672 patches/expected. Действуют прежние атомарные
проверки прав, закрытых дней и ожидаемых значений каждой изменяемой ячейки.

Обновление данных не заменяет исходные ожидания черновика. Конфликт требует
сравнения «Было / Сейчас / Мой выбор» и явного подтверждения. Неопределённый
сетевой результат повторяется с прежним request UUID и неизменным телом.
Успешная запись с ошибкой последующего чтения не отправляется второй раз.

Черновик хранится только в памяти открытой вкладки. Есть защита навигации
и beforeunload, но принудительное закрытие/перезагрузка с подтверждением
теряет несохранённый ввод. Ни localStorage, ни серверное autosave не добавлены.

## Приёмка

1. Открыть `http://localhost:5177/audit-calendar?view=availability`.
2. Проверить верхние controls и свёрнутый период; выбрать своего участника.
3. Изменить несколько ячеек в разных днях. До сохранения записи не отправляются.
4. Исправить выбранную ячейку или отменить весь черновик крестиком рядом
   с «Сохранить». Повторить ввод.
5. Нажать «Сохранить»: увидеть индикатор и «Изменения сохранены».
   Обновить календарь и убедиться, что значения сохранились.
6. На телефоне заполнить два разных дня и сохранить их одним действием.

Local candidate: прежний порт 5177, backend 8004. Обновляется только frontend.
Откат: прежний frontend image, без отката БД. Сначала завершить или отменить
черновики в открытых вкладках. Commit/release/deploy требуют отдельного решения.
