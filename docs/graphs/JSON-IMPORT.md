# JSON-импорт графов

Пункт **2.12** [исходного чек-листа от 24.09.2026](ACCEPTANCE-2026-09-24-ORIGINAL.md).
Локальный адрес приёмки: **http://localhost:55177/graphs**.

## Граф и данные JSON

Корректный JSON не обязательно является сохранённым графом. Например,
`{"project":"Релиз","ready":false}` является корректным JSON, но не содержит
узлов, связей и состояния графа. Его можно преобразовать режимом `tree`.

Сохранённый граф DPMS содержит массивы `nodes` и `edges`, идентификаторы,
координаты, виды, активный вид и служебные поля. Полный контракт хранения:
[`backend/app/schemas/graph.py`](../../backend/app/schemas/graph.py).
Самый надёжный пример этого формата получается экспортом уже созданного графа.
Наличие двух массивов определяет формат `native`, но само по себе не гарантирует
валидность документа: после определения формата необходима проверка графа.

Импорт работает локально, без сети, внешнего ИИ, выполнения кода из JSON и
отправки данных в облако. Эта реализация не импортирует Excel или DOCX,
не извлекает сущности с помощью ИИ и не обещает таких возможностей.

## Режимы

| API-режим | Что импортируется | Обработка |
| --- | --- | --- |
| `native` | Существующий граф с массивами `nodes` и `edges` | Существующий `adaptImportedGraph` и проверка графа в main |
| `cubes` | Экспорт «Кубики» с массивом `cubes` | Существующий адаптер «Кубики» в main |
| `tree` | Любое JSON-значение в пределах лимитов | Иерархия «свойство/индекс: значение», один узел на значение |
| `records` | Выбранный массив объектов | Узел на строку, атрибуты в описании, необязательные связи родитель → ребёнок |
| `edges` | Выбранный массив объектов связей | Сущности из значений source/target, направленные связи между ними |

Автоопределение сначала проверяет `native`, затем `cubes`. Непустой корневой
массив объектов с хотя бы одной парой полей `source`/`target`, `from`/`to`,
`sourceId`/`targetId` или `source_id`/`target_id` определяется как `edges`.
Другой непустой массив объектов определяется как `records`; остальное как `tree`.
Это эвристика, а не валидация каждой строки. Неполная строка связей затем даст
понятную ошибку. Пустой массив по умолчанию становится узлом дерева; явно
выбранные `records`/`edges` создают пустой граф с предупреждением.

`mode: 'tree'` принудительно рассматривает даже native/cubes JSON как данные.
Массив внутри объекта выбирается через `recordPath`, а не автоматически.

### Дерево данных

```json
{
  "project": "Релиз",
  "ready": false,
  "count": 0,
  "owner": null,
  "steps": ["Проверка", {"title": "Публикация"}]
}
```

```js
convertStructuredJson(parsed, { mode: 'tree' }, 'release.json');
```

Корень имеет `sourceRef: ''`, поле `ready` имеет `/ready`, объект второго шага
имеет `/steps/1`, его название имеет `/steps/1/title`. Корневые скаляры `0`,
`false`, `null`, строки, пустые объекты и вложенные массивы тоже поддерживаются.
Связи идут от родителя к непосредственным детям. Узлы размещаются в
детерминированной сетке; это не автоматическая семантическая классификация данных.

### Записи

```json
{
  "items": [
    {"id": "P-1", "name": "Релиз", "parentId": null, "ready": false},
    {"id": "T-1", "name": "Проверка", "parentId": "P-1", "estimate": 0}
  ]
}
```

```js
convertStructuredJson(parsed, {
  mode: 'records',
  recordPath: '/items',
  idField: 'id',
  titleField: 'name',
  parentField: 'parentId'
}, 'tasks.json');
```

Порядок строк сохраняется. Родитель может находиться после ребёнка. Все
атрибуты строки сериализуются в `description` с оговорённым ниже сокращением.
Узлы имеют ссылки `/items/0`, `/items/1`. Данные вне `/items` не включаются:
это явно отражается в `issues`.

ID: непустая строка, конечное число или boolean. `0` и `false` являются ID;
`null`, пустая/пробельная строка, массив или объект ID не являются. Числовой
целочисленный ID вне безопасного диапазона JavaScript следует передавать
строкой, например `"9007199254740993"`; иначе кандидат отклоняется.
Типы значимы: число `1`, строка `"1"`, boolean `false` и строка `"false"`
не склеиваются. `-0` и `0` не различаются.

Если ID-поле определено, дубли и отсутствующий ID хотя бы в одной строке
отклоняют весь кандидат. Если ID-поля нет ни в одной записи, создаются
позиционные ID с предупреждением. При этом поиск родителя невозможен:
для `parentField` требуется настоящее `idField`. Отсутствующий родитель,
`null` и `""` означают корневую запись. Непустая ссылка на несуществующий ID
отклоняет импорт, а не создаёт вымышленного родителя. Ссылка записи на себя
сохраняется в данных и предупреждении, но ребро не создаётся. Циклы между
разными записями сохраняются как направленные связи, поэтому результат не
обязательно является деревом.

### Связи

```json
[
  {"source": "Команда", "target": "Релиз", "label": "готовит", "priority": 2},
  {"source": "Релиз", "target": "Проверка", "label": "включает"},
  {"source": "Команда", "target": "Проверка", "label": "выполняет"}
]
```

```js
convertStructuredJson(parsed, {
  mode: 'edges',
  recordPath: '',
  sourceField: 'source',
  targetField: 'target',
  labelField: 'label'
}, 'relations.json');
```

Результат: три сущности и три ребра. Повторное значение endpoint переиспользует
узел. Правила значений и типов совпадают с правилами ID записей. `sourceRef`
сущности указывает на первое появление endpoint, например `/0/source`.
В описание обоих endpoint добавляются исходные строки связей, включая
неиспользованные атрибуты. Для самоссылки строка добавляется только один раз.

Схема графа не разрешает самосвязи и несколько рёбер одной направленной пары:
самоссылки не создают ребро, у повторов сохраняется первое ребро с первой
подписью. Каждый такой случай отражается в `issues` с номером строки.
Исходные строки отражаются в описаниях с учётом возможного сокращения, а не
теряются молча. `A → B` и `B → A` являются разными связями. Пустая или
отсутствующая подпись заменяется на `связано с`; `0` и `false` сохраняются
как подписи. Объект или массив вместо подписи является ошибкой.

## Параметры полей

| Параметр | Значение по умолчанию / правила |
| --- | --- |
| `mode` | Автоопределение; явные значения только `tree`, `records`, `edges` |
| `recordPath` | `''` — корень; JSON Pointer для массива записей/связей |
| `idField` | Первый присутствующий: `id`, `ID`, `_id`, `uuid`, `code` |
| `titleField` | Первый присутствующий: `title`, `name`, `label`, `displayName`, `display_name` |
| `parentField` | Первый присутствующий: `parentId`, `parent_id`, `parent`, `parentID` |
| `sourceField`, `targetField` | Первая обнаруженная пара из перечисленных выше; иначе `source`, `target` |
| `labelField` | Первый присутствующий: `label`, `relation`, `type`, `name` |

Автоопределение выбирает поле для всего массива, не отдельное поле на каждой
строке. Пропуск параметра, `undefined` и `''` включают автоопределение.
Пустое имя поля не отключает найденный `parentField`. Явно заданное непустое
имя, отсутствующее во всех строках, является ошибкой. Пустой/отсутствующий
заголовок записи заменяется ID или номером строки, с предупреждением, если
поле заголовка было выбрано. Имена полей буквальные: `a.b` обозначает ключ
`"a.b"`, а не вложенный путь. Отдельного mapping заголовков сущностей в
режиме `edges` нет: заголовком служит значение endpoint.

JSON Pointer: `/data/items` выбирает `input.data.items`; `~1` означает `/`,
`~0` означает `~`. Например, ключ `a/b` и вложенный ключ `~rows` дают
`/a~1b/~0rows`. `''` означает весь документ, `/` означает поле с пустым именем.
Для индексов массива допустимы только `0`, `1`, ...; `01`, `-`, `length`,
URI-фрагменты `#/...` и неверные escape-последовательности отклоняются.
`recordPath` с непустым значением неприменим к `tree`.

## Лимиты и безопасность

- До **1500 узлов** и **3000 рёбер**. В `edges` допускается не более 3000
  исходных строк до удаления повторов. В `records` не более 1500 строк.
- Разобранный JSON после компактной сериализации и итоговый граф: до **5 МБ
  UTF-8** каждый. Main отдельно ограничивает размер исходного файла.
- Вложенность JSON: до **512** переходов от корня. Проверка и обход используют
  явный стек, не рекурсивные вызовы. Глубина дерева дополнительно ограничена
  точной длиной `sourceRef`: **300 символов**.
- Превышение структурных лимитов, пути или размера отклоняет **весь кандидат**.
  Узлы и связи не обрезаются до допустимого количества.
- `description` ограничен **2000**, заголовок узла **180**, подпись ребра **80**,
  название графа **80** символами. Сокращение текста отмечается в `issues`,
  а сокращённое описание также содержит явную пометку. Граф с сокращениями
  не является полной резервной копией данных; сохраняйте исходный файл.
- Координаты генерируются в допустимом диапазоне; пользовательские поля
  `x`, `y`, `scale`, `color` и подобные остаются данными, не настройками графа.
- Вход и `options` не изменяются; результат не содержит ссылок на их объекты.
  Нет DOM, сети, localStorage, `eval`, вызова `toJSON` или геттеров.
- Принимаются разобранные JSON-значения, обычные объекты (также с null-prototype)
  и плотные массивы. Циклические ссылки, функции, `undefined`, BigInt, Symbol,
  NaN/Infinity, аксессоры, скрытые свойства и пользовательские прототипы
  отклоняются, а не теряются при сериализации.
- `__proto__`, `constructor`, `prototype` и другие имена сохраняются как
  обычные данные. Mapping и JSON Pointer обращаются только к собственным
  свойствам. Из значений не создаются имена свойств прототипов или ID узлов.
- HTML и URL сохраняются **как текст**, не как разметка. Main обязан показывать
  все строки, имена файлов, ошибки и `issues` через `textContent` либо штатный
  `escapeHtml`; нельзя вставлять их в `innerHTML` без экранирования. Адаптер не
  является HTML-sanitizer и не делает строку безопасной для любого DOM-контекста.

Описание содержит JSON-представление разобранного значения, а не точную копию
байтов файла: пробелы и запись чисел могут отличаться. Уже потерянные при
`JSON.parse` повторные ключи объекта или точность чисел адаптер восстановить
не может. Большие идентификаторы следует хранить строками.

## Контракт интеграции

Файл: [`import-adapters.mjs`](../../frontend/public/graph-workspace/import-adapters.mjs).
У модуля нет зависимостей. Main подключает его из `script type="module"`:

```js
import { detectJsonMode, convertStructuredJson } from './import-adapters.mjs';

const parsed = JSON.parse(await file.text());
const detected = detectJsonMode(parsed);
// native/cubes: существующий adaptImportedGraph(parsed, file.name).
// Данные: mode и mapping берутся из выбора пользователя.
const { graph: candidate, issues } = convertStructuredJson(
  parsed,
  { mode: 'records', recordPath: '/items' },
  file.name
);
```

`detectJsonMode(input)` возвращает `'native' | 'cubes' | 'tree' | 'records' |
'edges'`. `convertStructuredJson(input, options = {}, fileName = 'import.json')`
возвращает `{ graph, issues: string[] }`. Обе функции могут бросить `Error`
с русским сообщением; `input` должен быть **разобранным значением**. Переданная
строка, даже похожая на JSON, считается строковым скаляром, не исходным кодом JSON.

Результат является полным `GraphPayload v3`: `nodes`, `edges`, пустые `groups`
и `audit`, один вид с позициями и `activeViewId`. ID узлов и рёбер определены
порядком обхода; ID графа детерминирован по входу, режиму, mapping и имени файла,
но не является криптографическим идентификатором. Повторный вызов с теми же
аргументами даёт тот же результат. Служебные даты кандидата равны
`1970-01-01T00:00:00.000Z` для чистоты функции. При подтверждённом импорте main
назначает новый ID графа, актуальные даты и запись аудита, как в прежнем импорте.

Main отвечает за UI выбора режима/полей, предварительный просмотр числа узлов
и связей, вывод **всех `issues`**, подтверждение, окончательную проверку и
атомарное локальное сохранение. Ошибка не должна менять текущий граф.
Этот модуль не подтверждает и не сохраняет импорт самостоятельно. Раздел
описывает контракт интеграции; реализация UI находится в отдельном scope main.

## Проверка

Из корня репозитория:

```sh
node frontend/scripts/test-graph-imports.mjs
```

Проверки охватывают пять режимов детектора, скаляры, вложенные массивы,
иерархию, mapping, escaped pointers, дубли/пропуски ID, отсутствующего родителя,
ссылки на себя, повторные направленные пары, типизацию endpoint, unsafe keys,
неизменность frozen-входа, отсутствие вызовов геттеров и `toJSON`, границы
схемы и текста, лимиты 1500/3000, размер UTF-8, размер результата и глубину
20 000 без переполнения стека. Проверка DOM-экранирования и UI-предпросмотра
должна выполняться интеграционными тестами main на единственном адресе приёмки.
