# Раздел «Графы» в DPMS

## Текущий слайс

Первый кандидат встраивает проверенный standalone-прототип как отдельный раздел
DPMS по маршруту `/graphs`. Основная оболочка сохраняет навигацию и учётную
запись DPMS, а рабочее пространство исполняется из статического same-origin
snapshot `frontend/public/graph-workspace/index.html`.

Исходный прототип:

```text
/Users/bogdanov/Code/dpms-graphs-prototype/index.html
```

Snapshot намеренно изолирован от React-кода. Это позволяет перенести текущий UX
без частичной переписи и сохраняет границу для будущего самостоятельного
приложения. Готовность workspace подтверждается origin-independent сообщением
`postMessage`, поэтому будущий отдельный origin не потребует чтения DOM iframe.

## Данные и доступ

- раздел доступен каждому авторизованному пользователю;
- пункт можно переставлять или скрывать через существующий конфигуратор меню;
- графы остаются локальными для браузерного профиля, хранятся в `localStorage` и
  разделяются по `user.id`, чтобы обычная смена учётной записи не открывала
  холст предыдущего пользователя;
- backend, общая БД, совместное редактирование и DPMS entity API пока не подключены;
- импортированные файлы обрабатываются в браузере и не отправляются на backend.

Разделение ключей `localStorage` снижает риск случайного показа данных между
учётными записями одного браузера, но не является серверной авторизацией. До
подключения backend нельзя использовать этот слайс как защищённое общее хранилище.

## Обновление snapshot

После принятого изменения standalone-прототипа его `index.html` копируется в
`frontend/public/graph-workspace/index.html`. После копирования обязательны:

```bash
cd frontend
npm run build
npm run smoke:navigation
npm run test:graphs
```

Затем проверяются `/graphs`, импорт JSON, сохранение после reload, desktop и
iPhone layout. Production deploy выполняется только после отдельного разрешения.

## Следующая архитектурная граница

При развитии отдельного приложения статический snapshot заменяется версионируемым
frontend package или отдельным origin. До этого момента нельзя обещать серверную
синхронизацию, общие графы между устройствами или наследование прав связанных
сущностей DPMS. Перед сменой origin потребуется явная миграция локальных графов:
новый origin не получит автоматический доступ к текущему `localStorage`.
