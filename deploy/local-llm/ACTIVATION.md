# Локальная модель: активация 17.09.2026

Документ фиксирует первичную активацию до инфраструктурного релиза. Действующий
app release определяется release manager; сохранение коннектора при новых
релизах описано ниже.

Статус: private HTTPS-маршрут production VPS -> Mac активирован и подтвержден.
Приложение остается на `dpms-bb8261f03820`; backend и audit-worker пересозданы
с прежними точными SHA образов. Релиз приложения, миграции, создание ИИ-профиля
и обработка реальных документов не выполнялись.

## Согласованный Scope

Пользователь разрешил узкое открытие маршрута, дополнение HTTPS allowlist,
необходимый перезапуск двух контейнеров, синтетическую проверку и откат.
Имена/адреса остаются только в закрытых runtime-файлах; секретные конфигурации
не читались. Собственный Bearer шлюза извлекался fixed helper из собственного
Keychain item и передавался тесту только через SSH stdin, без вывода и файлов.

## Подтверждено

- 120 local tests PASS; Python compile, shell syntax, diff check PASS.
- Два полных native stop/start цикла Mac после execve fix PASS: PID службы
  совпадает с PID единственного listener; stop удаляет процесс и listener.
- Private Tailscale Serve, проверяемый TLS, Funnel выключен.
- VPS: TLS401 без Bearer по IPv4 и IPv6; TCP22/80/8080/18080 закрыты.
- Backend/audit-worker: DNS/TLS401; email/deadline-worker не соединяются
  с endpoint по IPv4 и IPv6. Это не доказательство защиты от root/Docker-admin.
- По два последовательных синтетических вызова из каждого нужного контейнера:
  штатный `generate_text` DPMS -> private HTTPS -> gateway -> llama.cpp.
  Каждый ответ содержит две непустые записи требуемой структуры.
- Остановка собственного gateway дала 502 обоим контейнерам. После старта
  восстановлены TLS401 и успешные синтетические provider calls.
- Сетевой rollback и полный rollback двух контейнеров реально выполнены.
  Проверены восстановленные origins, исходные SHA образов, изоляция и health200.
- После повторной активации настройки и SHA повторно проверены, выполнен
  `confirm`; временный rollback timer остановлен. Bounded critic: GO.

Схема из двух элементов проверяет транспорт/формат, не полноту реального ТЗ.
`db_writes: 0` в smoke описывает кодовый путь без DB API, а не измерение всех
записей работающей многопользовательской системы. Это не полный audit-job E2E.

## Устройство И Откат

- Root runtime: `/etc/dpms/local-llm/`. Идентичности сети, origins и image inventory
  находятся там, файлы 0600. Значений ключа там нет.
- `connector.override.json` добавляет один origin и точное `extra_hosts` только
  двум сервисам. Общий DNS VPS не меняется, старые origins сохранены.
- `activation.pins.json` фиксирует исходные image SHA только для операции
  активации/отката. Для обычных будущих app releases этот файл не подключать.
- Контроллер в `/usr/local/lib/dpms-local-llm/install_activation.py` сериализует
  операции через flock; trial имеет отдельный nonce, deadline и boot identity.
  Устаревший timer не откатывает новую либо уже подтвержденную активацию.
- Guard обновляется каждые 20 секунд, контейнерные разрешения истекают за 90.
  Ошибка проверки возвращает quarantine; при отказе nft пробует отключить tailnet.
  Неподтвержденный trial после reboot/deadline не открывает маршрут.
  Физический reboot VPS в этой проверке не выполнялся.
- Явный rollback сначала закрывает маршрут, независимо пытается восстановить
  конфигурацию двух сервисов. Отсутствующий контейнер восстанавливается в trial;
  обнаруженный другой релиз не откатывается автоматически на старые образы.

На самом VPS оператор может выполнить:

```sh
sudo python3 /usr/local/lib/dpms-local-llm/install_activation.py rollback
```

После смены app release старый image inventory требует отдельного пересмотра.
Не удалять marker/config вручную, не использовать полный firewall flush и
не заменять всю Tailscale policy. Откат оставляет установленные, но неактивные
guard-файлы; это не удаление Tailscale, модели или данных приложения.

## Следующий Релиз И Остаточные Gates

В runtime-копии `dpms-node.sh` и `dpms-export-backup.sh` внесены только хуки
подключения overlay при наличии `compose-activated`; исходники таких же изменений
есть в этой ветке. Созданы резервные копии служебных скриптов до правки.

Исходники коннектора и overlay hooks включаются в инфраструктурный релиз поверх
актуального приложения. Runtime-файлы, адреса и значения ключей в Git не входят;
новый VPS требует отдельной настройки и разрешения на подключение.

При promote/rollback release manager блокирует конкурирующую активацию и требует
подтвержденного состояния коннектора. Затем останавливает refresh, закрывает
маршрут собственной quarantine-таблицей и только после этого пересоздает сервисы.
Свежие разрешения для новых адресов контейнеров применяются до возобновления
таймера. Ошибка до resume оставляет маршрут закрытым: не включать таймер вручную,
пока не подтверждены состав контейнеров и конфигурация. Это устраняет окно,
когда переиспользованный Docker IP мог бы получить чужое прежнее разрешение.

Следующий разрешаемый отдельно шаг: зарегистрировать локальный ИИ-профиль в БД
через admin UI, безопасно задать его собственный Bearer, проверить синтетический
audit job целиком, затем согласовать один реальный документ. Сейчас существующие
профили не изменены. При недоступном Mac нет автоматического перехода на облако.
Физический sleep/reboot Mac и бизнес-путь pause/resume еще не проверены.
Login LaunchAgent требует входа пользователя, не заменяет unattended server.
