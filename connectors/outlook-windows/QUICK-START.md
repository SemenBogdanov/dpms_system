# Outlook -> DPMS: практическое подключение

Актуально 17.11.2026 для EXE 0.1.0 / source `01541ca`.

## Что сейчас работает и чего не хватает

- Пользователь подтвердил: EXE запускается на рабочем Windows.
- Пользователь подтвердил: сайт DPMS на рабочем компьютере не открывается.
- Backend/frontend для почты подготовлены в Git, но **в production не выпущены**.
- Новые таблицы БД ещё не созданы; рабочий адрес HTTPS-приёмника не выдан.

**Да, DPMS нужно обновить на сервере.** Копирование EXE само по себе не добавляет
серверный API, таблицы и раздел настроек. Пока этот шаг не выполнен, получить
рабочий код подключения на старом сайте нельзя. Пароль DPMS в поле кода не подойдёт.
Этот документ не является разрешением на production deploy или экспорт почты.

Для Windows не нужны Python, PostgreSQL, Node.js, Visual Studio и отдельная
установка .NET: runtime включён в EXE. Перекомпилировать запустившийся файл
для настройки подключения не требуется.

## 1. Что куда копировать

На рабочий Windows переносится разрешённым IT способом только
`DPMS.OutlookConnector.exe`. Документы и `source/` нужны для проверки, но не
для работы клиента. `connection.state`, пароли и настройки другого компьютера
переносить нельзя: подключение создаётся заново для текущего Windows-пользователя.

1. Распакуйте ZIP через «Извлечь всё». Не запускайте EXE прямо из окна ZIP.
2. Поместите EXE в постоянную папку, согласованную с IT. Пример для обычного
   пользователя: `%LOCALAPPDATA%\Programs\DPMS-OutlookConnector`.
3. Запускайте EXE обычным двойным щелчком, **не «От имени администратора»**.
4. Если он уже распакован и запускается, ничего переустанавливать сейчас не нужно.
5. Пока не включайте «Запускать при входе в Windows» и автоматическую передачу.

При желании IT проверяет файл без запуска:

```powershell
Get-FileHash .\DPMS.OutlookConnector.exe -Algorithm SHA256
```

Ожидается `c41f4d734cc17ae9934d535272933c6ba7954b9eb3b30b096fdb1d89d5a902f8`.
Подписи организации у этой сборки нет. Не обходите SmartScreen/антивирусную
блокировку: в таком случае нужен допуск IT, а не отключение защиты.

## 2. Выбрать маршрут с рабочего компьютера

Сайт у вас не открывается. Это ещё не доказывает недоступность самого API,
например через разрешённый proxy; маршрут клиента нужно проверить отдельно.
Если IT выберет отдельный приёмник, возможна такая схема:

```text
Рабочий Windows + Outlook -> разрешённый HTTPS-приёмник -> основная БД DPMS
Другое разрешённое устройство -> сайт DPMS -> создание кода и просмотр почты
```

Приёмник можно разместить рядом с БД, **если** этот узел действительно доступен
по разрешённому HTTPS и IT разрешает новый сервис. Gateway пока не установлен.
Это не обход корпоративных ограничений: адрес/порт и экспорт должны быть одобрены.

На рабочем Windows в обычном PowerShell выполните две точечные проверки.
Вместо `DB_HOST` укажите известное вам имя/IP сервера БД. Не присылайте сам адрес,
полный сетевой вывод или credentials; нужны только два значения True/False.

```powershell
Test-NetConnection -ComputerName 'DB_HOST' -Port 443 -InformationLevel Quiet -WarningAction SilentlyContinue
Test-NetConnection -ComputerName 'DB_HOST' -Port 5432 -InformationLevel Quiet -WarningAction SilentlyContinue
```

Это проверки TCP, не изменение настроек, не чтение БД и не сканирование диапазона.
Если организация ограничивает такую диагностику, поручите её IT.
[Microsoft: Test-NetConnection](https://learn.microsoft.com/en-us/powershell/module/nettcpip/test-netconnection?view=windowsserver2025-ps).

| Результат | Следующий шаг |
| --- | --- |
| 443=True | Можно проверять согласованный HTTPS-маршрут. Это ещё не доказывает наличие API или правильного сертификата |
| 443=False, 5432=True | Доступен SQL-порт, но текущий EXE не умеет SQL. Нужен разрешённый HTTPS endpoint либо отдельно спроектированный новый transport |
| Оба False | Нужен маршрут, утверждённый IT; настройкой EXE это не исправить |
| TCP443=False, но разрешённый HTTPS proxy существует | Прямой TCP-тест не проверяет proxy-туннель. IT отдельно проверяет доступ через proxy; не отключать его |

Не вводите `http://`, строку `postgresql://`, SQL-порт5432 или пароль базы в EXE.
Ping сервера не подтверждает ни один из этих вариантов. Не меняйте firewall,
TLS и корпоративные политики самостоятельно.

## 3. Однократная работа администратора: обновить DPMS

Это серверная работа, не копирование файлов на рабочий Windows. Выполняется
после отдельного approval через штатный DPMS release protocol с backup.

Администратор должен:

1. Подготовить, пока не активируя, backend и frontend Outlook-функции из source
   `01541ca4b0573fca8be276a8a106dbf0162d6d25` либо отдельно проверенного его потомка.
   Одного обновления frontend недостаточно. Более поздний docs-only commit не
   означает новую версию EXE.
2. Сделать и проверить backup основной БД, сверить её фактическую revision,
   затем применить согласованную migration `099 -> 100_mail_import`.
   Она добавляет `mail_import_devices`, `mail_import_items`,
   `mail_import_attachments`. Новую PostgreSQL на Windows устанавливать не нужно.
3. После готовности схемы активировать согласованный release и проверить основной
   API и интерфейс сайта. Не выставлять новую функцию до готовности её таблиц.
4. Если после проверки маршрута IT выбрал отдельный gateway, развернуть его на
   согласованном доступном узле. ASGI entry point: `app.mail_import_gateway:app`.
   Он должен использовать **ту же primary DB**, что сайт, не тестовую копию.
5. До внешнего открытия gateway подготовить DNS/HTTPS-сертификат и reverse proxy, согласованные firewall/egress
   rules, request-size/rate/concurrency/timeouts. Gateway предоставляет только
   `POST /api/mail-import/pair` и `/api/mail-import/sync`, не owner UI/download API.
   DB credentials остаются в серверном runtime; не входят в ZIP или Windows EXE.
6. Проверить API и права, отсутствие неожиданных background services у gateway,
   миграцию, rollback-план и обмен на разрешённом тестовом профиле.
7. Передать вам **один точный HTTPS-адрес приёмника**, без пароля и без пути,
   и подтвердить готовность раздела «Outlook Inbox» на сайте.

После появления импортированных данных автоматический downgrade100 блокируется:
откат требует сохранения этих данных и отдельного плана, не команды удалить таблицы.
Универсальные SSH/docker-команды здесь намеренно не приведены: серверный topology
и endpoint ещё не утверждены. Не копируйте Python-файлы вручную в production.

## 4. Получить одноразовый код на сайте

Выполнять **после подтверждённого обновления DPMS**, на устройстве, где сайт
доступен и вход разрешён организацией. Это может быть другое устройство, не
рабочий Windows. Сайту и gateway нужна одна БД; иначе код не сработает.

1. Войдите в свой аккаунт DPMS и откройте «Настройки» (`/settings`).
2. Найдите блок **Outlook Inbox**. Его отсутствие на старом сайте ожидаемо до release.
3. В поле «Название устройства» введите, например, `Рабочий Windows`.
4. Для согласованного полного переноса оставьте «Передавать текст писем» и
   «Передавать вложения». Это разрешение на экспорт, а не только отображение.
5. Нажмите **«Создать подключение»**.
6. Появится **«Одноразовый код привязки»**. Используйте его в течение10минут;
   он работает один раз и после закрытия не отображается повторно.
7. Перенесите код только разрешённым защищённым способом, не в чат с агентом,
   не в документ/скриншот и не через неутверждённый сервис обмена.

Если код потерян/истёк, отзовите ненужное pending-подключение и создайте новое.
Для уже импортированного ящика не уменьшайте grants нового устройства относительно
старого: сервер специально блокирует такое подключение от перезаписи полных данных.

## 5. Заполнить окно EXE

Откройте classic Outlook с нужным разрешённым профилем и дождитесь загрузки Inbox.
Программа читает default Inbox этого профиля, не произвольный выбранный shared folder.

| Поле/кнопка | Что ввести или сделать |
| --- | --- |
| «Адрес приёмника» | Точный HTTPS origin от администратора. Например `https://mail-ingest.example.org` - только пример, не рабочий адрес |
| «Код подключения» | Одноразовый код из блока Outlook Inbox; не пароль Outlook/DPMS/БД |
| «Период, дней» | 1..90. Для разрешённого тестового профиля начните с1; default30 |
| «Подключить» | Привязывает устройство; автоматический импорт ещё выключен |

В адресе не добавляйте `/settings`, `/api/mail-import`, `/pair` или `/sync`:
пути программа добавляет сама. Не используйте IP вместо согласованного hostname,
если сертификат выдан на имя. Пока администратор не выдал реальный адрес,
на этом шаге нужно остановиться, а не подбирать адреса.

После подключения проверьте имя аккаунта DPMS и выбранный объём данных.
Ожидаемый статус: **«Подключено. Синхронизация на паузе.»**

## 6. Первая передача и проверка

**В клиенте нет выбора одного конкретного письма.** Даже период1день переносит
все поддерживаемые входящие сообщения за этот период. Не используйте рабочий
профиль с конфиденциальной почтой для «пробного письма» без допуска на весь scope.
Для приёмки нужен разрешённый тестовый профиль/ящик с synthetic сообщениями.

1. На тестовом профиле подготовьте обычное входящее письмо, небольшое вложение
   и приглашение на встречу. Автозапуск пока оставьте выключенным.
2. Нажмите **«Синхронизировать»**: это один ручной проход, не включение timer.
3. Дождитесь статуса, количества переданных и пропущенных items.
   «Перенос неполный» не считать успешным завершением всего ящика.
4. В DPMS откройте **«Сообщения» -> «Почта и встречи»**
   (`/messages?tab=mail`) на устройстве с доступом к сайту.
5. Сверьте текст, отправителя, получателей, даты/встречу и содержимое вложения.
   Проверьте, что Outlook-письмо не удалено, не перемещено и не помечено прочитанным.
6. Повторите ручной проход: не должно появиться дублей. Проверьте отзыв, offline,
   паузу/выход и restart по security checklist до реального использования.
7. Если проверяли отзыв или переходите с тестового ящика на рабочий, создайте
   **новое подключение и новый код** на сайте. На Windows выполните «Отвязать»
   и снова шаги4-5 с нужным разрешённым Outlook-профилем. Старое подключение
   привязано к первому mailbox; смена ящика с ним намеренно блокируется.
   Перед новой передачей ещё раз проверьте профиль и разрешённый объём данных.
8. После приёмки и допуска нажмите **«Запустить»** для опроса примерно раз в60секунд.
9. При необходимости отдельно включите «Запускать при входе в Windows».
   Не перемещайте EXE после этого: автозапуск хранит путь к файлу.

Лимиты: до10MiB/вложение, до20MiB вложений/письмо,100файлов/письмо,2млн символов
каждого тела, до10000items/2GiB imported content в DPMS. Это Inbox за1..90дней,
не зеркало всей истории, Sent, Archive, shared folders или Calendar.

## 7. Если не подключается

| Что видно | Что проверить |
| --- | --- |
| Нет Outlook Inbox на сайте | Frontend ещё не обновлён либо открыт старый cached bundle; после подтверждённого release обновить страницу |
| «Не удалось загрузить подключения» | Готовность backend/API и migration100; это не исправляется повторным копированием EXE |
| «На этом адресе нет приёмника DPMS» | Адрес или deployment маршрута; старый сайт/SQL-host без gateway не подойдёт |
| «Нет соединения с приёмником» | Сеть, DNS, сертификат и разрешённый proxy; не отключать TLS verification |
| «Сервер перенаправляет запрос» | Нужен конечный HTTPS origin, который выдал администратор |
| «Доступ отклонён или отозван» при pair | Код истёк/использован, устройство отозвано либо сайт/gateway используют разные БД |
| «Конфликт данных, почтового ящика или лимита» | Не повторять бесконечно: проверить mailbox, прежний scope grants и quota с администратором |
| «Classic Outlook недоступен» | Открыт именно classic Outlook и рабочий профиль; New Outlook COM не поддерживает |
| «Перенос неполный» | Пропуски, недогруженные items или лимиты. Не считать все письма доставленными |

Если запрос pair завершился неоднозначно, код мог уже использоваться: проверьте
статус устройства на сайте перед повтором. Не присылайте код или body серверной
ошибки с почтовыми данными в чат.

## 8. Остановка и отключение

- «Пауза» останавливает опрос; «Синхронизировать» остаётся ручной командой.
- Крестик окна скрывает его в tray, **не завершает программу**.
- Для полного выхода: значок DPMS Outlook рядом с часами -> **«Выход»**.
- Для запрета будущего доступа: на сайте отозвать устройство. Уже импортированные
  данные сохраняются. Локальное «Отвязать» не заменяет серверный отзыв.
- Чтобы не запускалось при входе, снять checkbox автозапуска до удаления EXE.

## Что нужно прямо сейчас

1. Не перекомпилировать и не переустанавливать уже запустившийся EXE.
2. Передать два результата `443=True/False, 5432=True/False` с рабочего Windows.
3. Утвердить с IT маршрут и экспорт; затем отдельно согласовать серверный release.
4. После сообщения «сервер готов» выполнить шаги4-6 этой инструкции.

Сейчас открытый gate - сервер и сеть, а не поле логина в программе.
