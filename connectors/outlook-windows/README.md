# DPMS Outlook Connector

Локальный кандидат Windows-программы для одностороннего импорта default Inbox
classic Outlook в DPMS. Production, основная БД и корпоративный Outlook агентом
не менялись. Маршрут с рабочего компьютера ещё проверяется; ping недостаточно.

## Состав

- `Core`: HTTPS-протокол, разбиение доставки, checkpoint только после ACK.
- `Desktop`: Windows Forms/tray, Outlook COM worker, DPAPI storage.
- `Tests`: синтетические unit/HTTP tests, выполняются на Mac без Outlook.
- Серверный контракт: `../../docs/OUTLOOK-CONNECTOR-2026-11-16.md`.

Нужны Windows 11 x64 либо поддерживаемая Windows 10 LTSC/Enterprise x64,
classic Outlook с открытым рабочим профилем и доступный HTTPS-приёмник.
Обычная Windows 10 не входит в заявленную поддержку .NET 10; редакцию и lifecycle
проверить с IT по [матрице Microsoft](https://learn.microsoft.com/en-us/dotnet/core/install/windows).
New Outlook не поддерживается. Прямой PostgreSQL transport
не реализован; пароль основной базы в программе не используется.

## Сборка

Из корня репозитория, .NET SDK 10:

```sh
dotnet test connectors/outlook-windows/Tests/Tests.csproj -c Release
dotnet publish connectors/outlook-windows/Desktop/Desktop.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:DebugType=None -o connectors/outlook-windows/artifacts/win-x64
```

`artifacts/`, `bin/`, `obj/` исключены из Git. Self-contained EXE включает .NET;
устанавливать runtime на рабочем компьютере отдельно не требуется. Сборка не
подписана. Не обходить SmartScreen, antivirus или корпоративные ограничения:
разрешение/подпись/распространение согласуются с IT.

## Подключение После Подготовки Сервера

1. Подтвердить допустимость экспорта рабочей почты и вложений.
2. В DPMS: настройки, Outlook Inbox, название устройства, текст/вложения,
   создание подключения. Код одноразовый, действует 10 минут. Сайт DPMS можно
   открыть с другого разрешённого устройства, если он недоступен с работы.
3. На Windows открыть classic Outlook и `DPMS.OutlookConnector.exe`.
4. Ввести согласованный HTTPS-адрес приёмника и код. Не вводить пароль Outlook
   или PostgreSQL. Код не передавать в чат и не сохранять в документах.
5. Проверить имя пользователя DPMS и выбранный объём данных, затем «Запустить».
   Привязка сама по себе не включает автоматическую передачу.
6. Автозапуск Windows включается отдельным checkbox. Закрытие окна оставляет
   программу в tray; «Выход» в tray завершает её. «Пауза» прекращает опрос.

Настройки доступа защищены Windows DPAPI для текущего пользователя. Перенос
файла состояния на другой компьютер/пользователя не заменяет новой привязки.
«Отвязать» удаляет локальное подключение; серверный доступ отзывается отдельно
в DPMS. Уже импортированные записи при этом сохраняются.

Для уже импортированного ящика права можно расширить, но нельзя сузить:
подключение без ранее разрешённых текста или вложений получает конфликт,
даже после отзыва старого устройства. Новое подключение должно сохранять
прежний объём прав. Расширение добавляет недостающие данные той же версии
письма без сброса прочтения DPMS и без замены уже сохранённых файлов.

## Границы Данных

Default Inbox, включая полученные приглашения, изменения и отмены встреч.
Не зеркало Calendar, Sent, Archive, shared mailboxes или всей истории Exchange.
Период 1..90 дней, по умолчанию 30; снимок до 10 000 source items, страница до
5000. После ACK продолжается сохранённая очередь идентификаторов, в конце
начинается новый цикл. При превышении лимита снимка нужен меньший период.
Источник не помечается прочитанным, письма не перемещаются/не удаляются,
ответы и подтверждения встреч не отправляются.

Передаются исходный plain text/HTML, To/CC и вложения, если выбраны соответствующие
права. HTML в DPMS не исполняется, файлы не открываются автоматически.
Пределы: 2 млн символов каждого тела, 100 вложений, 10 MiB на файл, 20 MiB файлов
на письмо, 32 MiB JSON на запрос, 10 000 items/2 GiB imported content на владельца
в DPMS (текст, HTML, To/CC и decoded files).
Превышение или недоступное вложение означает пропуск всего item и статус неполного
переноса, а не молчаливое обрезание body/metadata-only fallback.

Отсутствие письма в следующем снимке ничего не удаляет из DPMS. Прочтение в DPMS
независимо от Outlook. При reconnect доставка повторяется без новых копий одной
и той же записи. «Последняя доставка» не доказывает свежесть Exchange: Outlook
может читать локальный кэш, в том числе offline.

Для embedded attachments Outlook может временно экспортировать файл в закрытую
per-user staging directory. Нормальный путь удаляет файл после чтения; при выходе
программа ждёт остановки scanner и cleanup. Остатки после crash очищаются при
следующем запуске. Этот путь, ACL и crash/kill проверяются отдельно на Windows.

## Проверка На Рабочем Windows

- Взять разрешённые тестовые письмо, файл и встречу, не реальную конфиденциальную
  переписку. Сверить текст, получателей, файл байт-в-байт, timezone и all-day.
- Повторить sync и перезапустить приложение: дубликатов нет, отметка прочтения
  DPMS сохраняется, Outlook не изменён.
- Отключить сеть, выполнить sync, вернуть сеть: данные доходят после повтора.
- Перенести/отменить тестовую встречу: новые входящие сообщения отражены,
  отсутствие старого сообщения не удаляет данные.
- Проверить Outlook closed/offline, policy prompt, паузу во время чтения,
  выход из tray, Windows 150%/200% DPI и автозапуск после входа.
- Отозвать устройство в DPMS: следующая доставка отклонена, автоматический
  опрос остановлен. Другой пользователь не видит запись и не скачивает файл.
- Проверить oversized/unsupported attachment и принудительное завершение worker:
  нет ложного статуса полного переноса; проверить cleanup temporary files.

Cross-build и синтетические тесты не заменяют эти проверки.
