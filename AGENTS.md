# DPMS: контекст работы с графами

## Обязательная синхронизация Git

Решение пользователя от 26.10.2026: каждая сессия разработки DPMS обязана
синхронизировать проверенные изменения с Git remote и подтвердить результат.
Перед работой и после неё выполнять
[протокол сессии разработки](docs/DEVELOPMENT-SESSION.md).

- В начале: fetch, status, branch/upstream и сравнение с актуальным remote.
  Старую dirty-папку нельзя объявлять текущим `main` по одному имени каталога.
- В конце: review своего scope, проверки, commit и push явного полного
  source/snapshot SHA в точный destination `refs/heads/<TARGET_BRANCH>`.
  Свежий `git ls-remote` должен подтвердить этот SHA и именно этот ref.
  `HEAD` подходит только при публикации текущего HEAD; snapshot без checkout
  проверяется по собственному SHA. Локальный commit не заменяет эту сверку.
- Push выполнять с явным refspec
  `<FULL_SOURCE_SHA>:refs/heads/<TARGET_BRANCH>` и `-c push.followTags=false`.
  Не использовать `--all`, `--mirror`, `--tags` или автоматический follow-tags.
  Зафиксировать baseline destination SHA (или ожидаемое отсутствие новой ветки)
  и повторно сверить непосредственно перед push. При concurrent remote change,
  отказе push или несовпадении итогового remote SHA остановиться, без force/retry.
- Чужие или непроверенные staged-изменения не включать в commit, не сбрасывать
  и не перезаписывать чужой index. Проверять staged diff только в allowlist;
  если свой scope нельзя изолировать, остановиться до commit.
- Незавершённый безопасный WIP сохранять в явно обозначенной `wip/` или
  `archive/` ветке; не включать его в `main` и не выдавать за готовый release.
- Не делать `git add .`, force push, blind merge, reset/clean или бессрочный
  stash ради зелёного status. Чужие изменения не откатывать.
- Secrets, credential-bearing configs, БД и runtime data не коммитить.
  Перед push проверять весь новый публикуемый delta, включая промежуточные
  commits, только в разрешённом scope и без вывода секретных значений.
- Если проверка или push невозможны, финальный статус: `не синхронизировано`,
  с точным остатком и следующим действием. Не утверждать «всё в Git».
- Git push не является production deploy. Согласование deploy остаётся отдельным.
